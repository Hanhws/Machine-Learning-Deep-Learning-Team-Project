# 차로·방향별 혼잡도와 지체 추정 (라벨 없이)

팀 주제 **"도로 대비 차량 면적 비로 교통 혼잡도 측정"** 을 확장한다.
도로를 사람이 그리지 않고 모델이 찾고, 방향·차로를 나눠 **차로별 혼잡도 → 추정 지체 시간** 까지 낸다.

- 입력: `../images/{train,val,test}` (AI-Hub 고속도로 CCTV 20,691장, 226클립) — 라벨 없음
- 차량: COCO 사전학습 YOLO26-seg (팀 파인튜닝 모델이 생기면 `s1_vehicles.py --weights` 로 교체)
- 도로·차선: Mapillary Vistas 사전학습 Mask2Former + 소실점 기하
- 방향: 우측통행 기하 규칙 + 자동 라벨로 파인튜닝한 ResNet18

## 먼저 알아둘 데이터 특징

| 특징 | 영향 | 대응 |
|---|---|---|
| 동영상이 아니라 **약 3초 간격** 사진 (클립 중앙값 약 6분) | 차량 추적·통과 대수·장기 예측 불가 | 사진 한 장으로 되는 **점유율** 을 쓴다 |
| 한 클립 안에서 **카메라가 회전** (수원 PRESET 001↔002, 부안 180° 반전 등) | 다른 화면의 배경·차량 위치가 섞여 차선이 망가짐 | `s1b` 에서 화면별로 분리 |
| 파일명 `TW2`·`OW5` = 양방향/한방향 + 차로 수 | 차로 수 채점 기준으로 쓸 수 있음 | `s2_summary.csv` 의 `lane_exact` |
| 카메라가 train/val/test 에 섞여 있음 | 같은 카메라로 학습·평가하면 과대평가 | 방향 CNN 은 카메라 단위로 분리 |

## 실행

```bash
cd 팀프로젝트
/opt/anaconda3/bin/python3.13 -m venv .venv      # Python 3.13
.venv/bin/pip install torch torchvision ultralytics transformers opencv-python scikit-learn scipy matplotlib pillow pandas
cd road_lane
./run_all.sh          # 전체 (Apple M5 기준 약 2시간, 대부분 1단계)
../.venv/bin/python report.py   # 발표용 수치·그림
```

각 단계는 끝난 클립·장면을 건너뛰므로 멈춰도 다시 실행하면 이어서 한다.

## 단계

| 파일 | 하는 일 | 주요 출력 |
|---|---|---|
| `s1_vehicles.py` | 차량 세그멘테이션, 차량을 지운 **배경 사진**(중앙값) | `outputs/s1/<clip>/` |
| `s1b_views.py` | 화면 전환 감지(사진 위쪽 특징 KMeans) → 윤곽선 유사도 0.7 이상이면 같은 구도로 합침 | `views.json` |
| `s2_road_lanes.py` | 배경 사진에 Mask2Former(1920 입력) → 소실점 → 각도(θ) 공간에서 분리대로 방향별 도로, 차선 도색 봉우리로 차로, 실선/점선·차량 이용률로 갓길 | `outputs/s2/<scene>/lanes_vis.jpg`, `s2_summary.csv` |
| `s2c_camera_groups.py` | **카메라 단위 도로 지도**: 같은 카메라에서 도로 영역 IoU ≥ 0.75·어긋남 ≤ 40px 인 장면을 묶고, 조건 좋은 장면(낮·소실점 강함)을 기준으로 도로 지도를 공유. G 방식 = 기준이 좋으면 도로·분리대만 투표 + 기준 장면 차선 도색, 기준이 약하면(밤·소실점 하위 1/3) 차선 도색까지 투표. 파일명 차로 수 기준 정확 41→48%, ±1 77→82% | `s2c_compare.csv`, `s2c_groups.json`, 원본은 `lanes_single.*` |
| `s2d_curves.py` | **휜 도로 대응**: 차로 수·방향·갓길은 그대로 두고 차로 모양만 보정. 방향별 도로마다 휨 곡선 g(y) 하나를 두고 모든 경계를 `소실점 직선 + g(y)` 로 함께 휘게 함(경계가 엇갈리지 않음). g 는 차선 도색·도로 가장자리 점을 방향별 도로가 보이는 가장 아래 행부터 위로 넓혀 가며 튀는 점을 버리는 릿지 다항식으로 맞추고, 근거가 끝난 위쪽은 마지막 휨 값으로 이어 칠함. 같은 바닥점으로 비교한 차로 중심 이탈도 0.192→0.174, 차로 포함률 52→62% (287장면 중 166개 좋아짐, 64개 나빠짐). 빈 차로 13/1,375개. 가까운 구간만으로 차로 수를 세는 방식은 정확 41→28% 로 나빠져 쓰지 않음 | 직선 지도는 `lanes_straight.*`, 평가 `s2d_reshape_eval.csv` |
| `s2b_direction.py` | 양방향 장면에서 자동 라벨(왼쪽 도로=앞모습, 오른쪽=뒷모습) → ResNet18 파인튜닝, CLIP zero-shot 과 비교 → 한쪽 도로만 보이는 화면에 방향 부여 | `outputs/s2b/eval.json`, `directions.json` |
| `s3_occupancy.py` | 차량을 바닥점으로 차로에 배정 → 차로·방향·도로 전체 점유율 (원근 보정: 가까운 구간에서 1/차로폭² 가중) | `outputs/s3/lane_frames.csv`, `peak.jpg`, `timeseries.png` |
| `s4_delay.py` | Greenshields: 속도 = 100·(1 − 점유율/정체점유율) → 1km 당 지체 → 원활/서행/정체 | `outputs/s4/scene_status.csv` |
| `report.py` | 차로 수 정확도, 방향 성능, **숨은 정체**(도로 전체는 원활인데 한 차로는 서행 이하) 비율 | `outputs/report/` |

## 한계 (발표 때 밝힐 것)

- **지체 시간은 미검증 추정값.** 이 데이터에 실제 속도가 없다. 한국도로공사 VDS(5분 단위 속도·점유율)와 같은 지점·시각을 맞춰야 검증할 수 있다.
- **15분~1시간 뒤 예측은 이 데이터로 불가.** 연속 시계열(VDS 등)이 필요하다.
- 차로 수는 한쪽 도로에서 ±1 틀리는 경우가 많다 (차선이 흐린 화면, 멀리 비스듬히 보이는 도로, 곡선 도로).
- 점유율은 차 높이가 뒤쪽 도로를 가리는 만큼 과대추정된다 (트럭, 카메라 가까운 곳).
- 방향 자동 라벨은 기하 규칙이 틀린 장면의 오류를 그대로 담는다 (차로 수가 파일명과 ±1 이내인 장면만 사용해 줄임).
