SAM3 차선 파이프라인

2026-09-16 · 기존 road_lane 2~4단계에 SAM3 를 붙인 실험 기록

Mask2Former 가 그리던 차선 도색만 SAM3 로 바꿨다. 나머지(도로·분리대·소실점·차로 기하)는 기존 코드 그대로다. 차로 수 정확도가 0.357 → 0.409 로 올랐고, 수원을 빼면 ±1 이 0.893 → 0.964 다.

한 줄 요약
SAM3 는 차선처럼 생긴 것을 찾는 데 강하고, 도로 면 같은 영역에는 약하다. 그래서 전부 갈아엎지 않고 차선만 교체하는 하이브리드가 가장 좋았다.

0. 무엇을 왜 했나

기존 파이프라인의 약점은 차로 수를 잘 못 센다는 것이었다(정확 0.357). 원인을 추적하면 2단계 관문 ①(도로 분할)·④(차로 경계)에서 차선 도색을 제대로 못 찾는 것이 컸다. Mask2Former 는 Mapillary Vistas 의 고정 클래스로 학습돼 있어 차선을 놓치는 장면이 있다.

SAM3 는 2025-11 에 Meta 가 공개한 개방어휘 분할 모델이다. "lane marking" 같은 짧은 명사구를 주면 그 개념의 모든 인스턴스를 찾는다. 고정 클래스 집합에 묶이지 않는 게 핵심이다.

SAM3 가중치는 게이트돼 있다. 자동 다운로드가 안 된다.

  2. 승인 후 토큰 발급 → hf auth login
  3. hf download facebook/sam3 sam3.pt --local-dir lane_sam3

라이선스는 Apache/MIT 가 아니라 Meta SAM License 다. 수업·연구 용도는 문제없지만 상업적 사용 전에는 약관을 봐야 한다. 실행은 전부 로컬이라 API 요금은 없다.

2. 처음엔 "완전히 새로" 만들어봤고, 실패했다

SAM3 로 차선을 찾아 직접 차로를 세는 독립 파이프라인을 먼저 만들었다 (lane_sam3/run_sam3.py → group_lanes.py). 소실점을 최소제곱으로 구하고, 조각을 기준선 x 위치로 묶고, 중앙분리대로 도로를 나누는 방식이다.

방식정확±1
기존 road_lane s20.3840.727
SAM3 독립 (차선수−1)0.2830.707
SAM3 독립 (점선수+1)0.3030.687

화면 전체 차로 수 기준, 공통 99장면. 숫자가 위 본문과 다른 건 잣대가 달라서다(방향별이 아니라 화면 합계).

기존보다 나빴다. 몇 시간짜리 기하 로직이 관문 7개로 다듬어진 s2 를 못 이긴다. 교훈은 분명했다 — 병목은 차선 검출이 아니라, 찾은 차선을 차로로 해석하는 기하였다. SAM3 는 앞쪽만 해결한다. 이 코드는 참고용으로 남겨뒀다.

3. 채택한 방식 — 하이브리드

두 모델의 출력을 비교해보니 갈리는 지점이 뚜렷했다.

같은 카메라 3장면도로 면적 (M2F)도로 면적 (SAM3)차선 (M2F)차선 (SAM3)
Buan_daemog 17:3041.3%27.1%3.2%3.1%
Buan_daemog 11:3038.6%12.6%4.6%2.7%
Buan_daemog 16:3019.6%35.9%0.5%5.3%

SAM3 의 도로 면적이 38.6% → 12.6% 로 튄다. SAM3 는 인스턴스 분할 모델이라 "도로" 같은 stuff 개념에 불안정하다. 반대로 3번 장면에서는 Mask2Former 가 차선을 0.5% 밖에 못 찾은 걸 SAM3 가 5.3% 찾아냈다.

그래서 각자 잘하는 것만 쓴다:

Mask2Former 도로(13) · 분리대(4,5,2,6,3) · 그 밖 모든 클래스
SAM3 차선 도색(24) ← 이것만 교체

구현은 lane_sam3/make_sam3_seg.py 이고, 실제로 하는 일은 두 줄이다. 기존 seg.png 에서 Mask2Former 차선을 지워 도로로 되돌린 뒤, SAM3 차선을 다시 그린다. 

seg = cv2.imread(base_seg, cv2.IMREAD_UNCHANGED).copy()
seg[seg == 24] = 13          # 기존 차선 → 도로
...
seg[sam3_mask] = 24          # SAM3 차선을 도로 위에 덮어 그림

차선을 도로 위에 덮어 그리는 순서가 중요하다. s2 는 asphalt = median(gray[seg == 13]) 으로 도색 판정 기준 밝기를 잡는데, 차선이 13 에 섞이면 그 기준이 흐려진다.

앞뒤(방향) 구분 — 두 가지를 겹쳐 쓴다

도로 검출 하나로 되는 게 아니라, 서로 독립인 두 근거를 교차 검증한다.

  1. 기하 규칙 — 우측통행이므로 화면 왼쪽 도로는 다가오고 오른쪽은 멀어진다. 양쪽 도로가 다 보일 때만 쓸 수 있다.
  2. ResNet18 — 차량 크롭을 앞모습/뒷모습으로 분류. 한쪽 도로만 보이는 화면에서도 쓴다.

5. 그대로 따라 하기

기존 outputs/ 기준 결과가 있다는 전제다. 1단계(차량 검출)와 Mask2Former 는 다시 돌리지 않는다.

# 0) SAM3 가중치 (위 2절 참고, 최초 1회)
cd 팀프로젝트
./.venv/bin/hf auth login
./.venv/bin/hf download facebook/sam3 sam3.pt --local-dir lane_sam3

# 1) 실험 폴더 준비 — s1(차량)·s2b(방향 모델)은 기준에서 복사
cd road_lane
EXP=runs/sam3
mkdir -p $EXP && cp -R outputs/s1 outputs/s2b $EXP/

# 2) SAM3 차선으로 seg.png 만들기 (236장면, 약 30분)
cd ../lane_sam3
../.venv/bin/python make_sam3_seg.py --out ../road_lane/$EXP

# 3) 2~4단계 (약 40분, 대부분 3단계)
cd ../road_lane
export ROAD_LANE_OUT=runs/sam3  PY=../.venv/bin/python
$PY s2_road_lanes.py            # 도로·차선  (끝에 2c 적용 전 정확도 출력)
$PY s2c_camera_groups.py --apply G
$PY s2d_curves.py apply
$PY s2b_direction.py apply      # 방향 적용 (학습은 다시 안 함)
$PY s3_occupancy.py
$PY s4_delay.py
$PY report.py

# 4) 색칠해서 눈으로 보기
cd ../lane_sam3
../.venv/bin/python vis_seg.py --run ../road_lane/runs/sam3 --sheet 6
실험 폴더를 재사용하지 말 것. 같은 폴더에서 다시 돌리면 2c·2d 가 옛 백업 (lanes_single.*, lanes_straight.*)을 읽어서 고친 결과가 무시된다. 실험마다 새 이름을 쓴다.

7. 한계 — 공유 전에 반드시 읽을 것

① 정답 자체가 못 미덥다

여기 모든 정확도는 파일명 차로 수(OW/TW+숫자)를 정답으로 잰 것이다. 그런데 pipeline_guide.html 7-3 할 일 0 에 적힌 대로, 무작위 24장면을 눈으로 확인하니 파일명이 제대로인 건 약 25% 였다. 즉 0.409 와 0.357 의 차이가 진짜인지 확정할 수 없다. 사람이 센 채점표(할 일 0)가 있어야 결론이 난다. lane_sam3/manifest.csv 에 lanes_true 빈 칸과 배경 102장이 준비돼 있다 — 6명이 나누면 1인당 17장.

② 수원은 오히려 나빠졌다

±1 이 0.463 → 0.338. 수원은 소실점이 약해서(강도 중앙값 0.65) 관문 ② 부터 흔들리는데, SAM3 가 차선을 더 많이 찾아내면서 오히려 흔들림이 커진 것으로 보인다. 수원이 68장면(29%)이라 전체 수치를 좌우한다. 다음 실험 1순위: 수원만 Mask2Former 차선 유지.

③ 데이터가 바뀌었다 — 옛 수치와 섞지 말 것

2026-09-16 에 원본 images/(20,691장·226클립)를 지우고 car_seg_split(8,500장·207클립)으로 교체했다. 지금 outputs/ 기준선은 새 데이터로 다시 만든 것이다. 발표 자료에 옛 수치(±1 82.2%)가 있다면 그대로 쓰면 안 된다.

④ 4단계 속도·지체는 미검증

점유율 → Greenshields 속도 → 지체 추정인데, 실측 속도가 없어 검증하지 못했다. occ_jam=0.6, v_free=100km/h 는 가정값이다. 등급('원활'·'서행')은 상대 비교로만 읽어야 한다.

⑤ 프레임이 연속이 아니다

car_seg_split 은 학습용으로 골라낸 데이터라 207클립 중 168개에 구멍이 있고 최장 연속 구간 중앙값이 8장이다. 3·4단계는 프레임 단위 집계라 정상 동작하지만, 시계열 그래프(__timeseries.png)는 구간이 끊겨 보인다. 연속 시계열이 필요하면 원본 images-*.zip 6개를 다시 받아야 한다.

⑥ 재현 환경 변경

SAM3 로드 시 timm·ftfy·wcwidth·clip 이 자동 설치된다. requirements.txt 에 기록해뒀다(clip 은 PyPI 가 아니라 git 설치). 기존 고정 버전은 하나도 바뀌지 않았고 check_env.py 18개 항목 전부 기준과 일치한다. 다만 SAM3 는 MPS 가 아니라 CPU 로 돈다 — 장면당 7초.

8. 다음에 할 일

  1. 수원만 기존 차선 유지 — 수원 밖 손해가 0이므로 전체 수치가 더 오를 가능성이 크다. 코드 몇 줄, 재실행 약 40분
  2. 채점표(할 일 0) — 어느 방식을 쓰든 결국 필요하다. 준비는 끝나 있다
  3. 할 일 1 (흐린 경계 삭제 순서) — scratch 에서 ±1 82.2 → 84.0% 확인됐지만 아직 코드 미반영
  4. SAM3 프롬프트 튜닝 — 지금은 "lane marking" 하나. "dashed lane line" 등 분리 시도
