# 집 노트북(Windows 11 + RTX 4070)으로 심사 기간 띄우기

RTX 4070 이면 YOLO 추론이 CPU 대비 20~30배 빠르다. 클라우드 CPU 서버보다 낫다.
대신 **안 꺼지게 만드는 것**과 **밖에서 보이게 하는 것** 두 가지가 숙제다.

저장소(`hantaeho123/traffic_project`)는 고치지 않는다. WSL2 안에 그대로 클론해서 돌린다.

---

## 1. WSL2 + 우분투

관리자 PowerShell 에서:

```powershell
wsl --install -d Ubuntu-24.04
```

재부팅 후 우분투가 열리면 사용자 이름·비밀번호를 정한다.

### systemd 켜기 (필수)

서비스를 계속 띄워 두려면 필요하다. 우분투 터미널에서:

```bash
sudo tee /etc/wsl.conf > /dev/null <<'EOF'
[boot]
systemd=true
EOF
```

그리고 **윈도우 PowerShell** 에서 `wsl --shutdown` 후 우분투를 다시 연다.

### 메모리 할당

WSL2 는 기본으로 전체 RAM 의 절반만 쓴다. 16GB 중 8GB 면 SAM3 가 CPU 로 떨어질 때 부족하다.
**윈도우 사용자 폴더**(`C:\Users\<사용자>\`)에 `.wslconfig` 파일을 만든다:

```ini
[wsl2]
memory=12GB
swap=8GB
```

`wsl --shutdown` 후 다시 열면 적용된다. (윈도우에 4GB 를 남겨 둔다)

## 2. GPU

**윈도우에만** 최신 NVIDIA 드라이버를 설치한다 (https://www.nvidia.com/Download/index.aspx).
**WSL 안에는 드라이버를 깔면 안 된다.** 윈도우 드라이버가 그대로 넘어온다.

확인:

```bash
nvidia-smi          # WSL 우분투 안에서. RTX 4070 Laptop 이 보이면 성공
```

### VRAM 주의

RTX 4070 Laptop 은 VRAM 8GB 다. `sam3.pt` 는 체크포인트만 3.3GB 이고,
등록 화면에서 **텍스트 프롬프트와 점/박스를 둘 다** 쓰면 코드가 예측기를 따로 올려 VRAM 이 모자랄 수 있다.
그때는 코드가 알아서 CPU 로 한 번 더 시도한다(느려질 뿐 죽지는 않는다).

**SAM3 는 카메라를 등록할 때만 돈다.** 등록이 끝나면 심사 기간 내내 YOLO 만 돌아가고,
YOLO 는 VRAM 2GB 면 충분하다. 그러니 등록을 먼저 끝내 두면 신경 쓸 일이 없다.

## 3. 밖에서 보이게 — 터널

가정용 인터넷은 공유기 뒤에 있어서 밖에서 바로 못 들어온다. 둘 중 하나를 고른다.

| | ngrok 무료 | Cloudflare Tunnel |
|---|---|---|
| 돈 | 0원 | 도메인값만 (약 1만원/년) |
| 주소 | `xxx.ngrok-free.app` 고정 1개 | `traffic.내도메인.com` |
| **첫 접속** | **경고 페이지가 한 번 뜬다** ("Visit Site" 클릭) | 바로 열림 |
| 설정 | 토큰 한 줄 | 로그인 + 명령 4개 |

심사위원이 처음 누르는 링크라 **경고 페이지 없는 Cloudflare 쪽을 권한다.** 도메인이 없으면 ngrok 으로 간다.

### (A) ngrok — 공짜, 대신 경고 페이지

1. https://dashboard.ngrok.com 가입
2. **Domains** 에서 무료 고정 도메인 1개 발급 (예: `brave-fox-123.ngrok-free.app`)
3. **Your Authtoken** 복사

설치 스크립트에 넘기면 알아서 systemd 서비스로 등록된다 (아래 5번).

### (B) Cloudflare Tunnel — 깔끔

도메인을 사서 Cloudflare 에 네임서버를 연결해 둔 뒤, WSL 우분투에서:

```bash
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main" | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt update && sudo apt install -y cloudflared

cloudflared tunnel login                         # 브라우저에서 도메인 선택
cloudflared tunnel create traffic
cloudflared tunnel route dns traffic traffic.내도메인.com

sudo mkdir -p /etc/cloudflared
sudo tee /etc/cloudflared/config.yml >/dev/null <<'EOF'
tunnel: traffic
credentials-file: /home/<사용자>/.cloudflared/<터널ID>.json
ingress:
  - hostname: traffic.내도메인.com
    service: http://localhost:8000
  - service: http_status:404
EOF

sudo cloudflared service install
sudo systemctl enable --now cloudflared
```

## 4. 파일 두 개 옮기기

윈도우 탐색기에서 `C:\Users\<사용자>\Downloads\` 에 넣어 두고, WSL 에서:

```bash
cp /mnt/c/Users/<사용자>/Downloads/provision-wsl.sh ~/
cp /mnt/c/Users/<사용자>/Downloads/yolo11s960_vehicle_best.pt ~/
```

맥에 있는 파일이라면 먼저 윈도우로 옮긴다. `sam3.pt`(3.3GB)는 굳이 옮기지 말고
허깅페이스 토큰을 주면 서버가 직접 받는다 (훨씬 빠르다).

## 5. 설치

WSL 우분투 터미널에서:

```bash
export ITS_API_KEY='ITS에서_발급받은_키'
export HF_TOKEN='hf_...'                          # SAM3 자동 다운로드용
export NGROK_AUTHTOKEN='...'                      # (A) 를 고른 경우만
export NGROK_DOMAIN='brave-fox-123.ngrok-free.app'  # (A) 를 고른 경우만
bash provision-wsl.sh
```

15~25분 걸린다. 끝나면 YOLO 가중치를 제자리에 놓고 재시작:

```bash
mv ~/yolo11s960_vehicle_best.pt ~/traffic/models/weights/yolov8s_seg_vehicle.pt
sudo systemctl restart traffic
```

확인:

```bash
sudo systemctl status traffic          # active (running)
sudo journalctl -u traffic -f          # 로그. "등록된 카메라 워커 N개 시작" 이 보이면 정상
curl -s localhost:8000/api/system | head -c 300
```

브라우저에서 `http://localhost:8000` (내 PC) / 터널 주소 (밖에서).

## 6. 안 꺼지게 — 여기가 제일 중요하다

클라우드와 달리 노트북은 **알아서 잠들고, 알아서 재부팅된다.** 세 가지를 막아야 한다.

### 절전·화면 끄기

설정 → 시스템 → 전원 및 배터리 → 화면, 절전 모드
- **전원 연결 시**: 화면 끄기 `안 함`, 절전 모드 `안 함`

### 뚜껑 닫아도 유지

제어판 → 전원 옵션 → **덮개를 닫을 때 수행할 작업** → 전원 사용 시 **아무 것도 안 함**

(노트북을 닫아 두려면 발열에 주의한다. 열어 두는 편이 안전하다.)

### Windows Update 자동 재부팅 막기

설정 → Windows Update → **업데이트 일시 중지** → 심사 기간(약 3주)만큼 미뤄 둔다.
재부팅되면 WSL 도 같이 내려가고 사이트가 죽는다.

### 재부팅되더라도 자동으로 살아나게

WSL 은 로그인해야 뜬다. 작업 스케줄러에 등록해 둔다.

1. 작업 스케줄러 → **작업 만들기**
2. 일반: 이름 `traffic-wsl`, **사용자가 로그온할 때만 실행**, 가장 높은 수준의 권한 ✓
3. 트리거: **로그온할 때**
4. 동작: 프로그램 `wsl.exe`, 인수 `-d Ubuntu-24.04 -u root /bin/true`
   (WSL 을 깨우기만 하면 systemd 가 traffic·ngrok 서비스를 자동으로 띄운다)
5. 조건: **컴퓨터의 AC 전원이 켜져 있는 경우에만 시작** 체크 해제

윈도우가 자동 로그인되게도 해 두면 완전 무인이 된다 (`netplwiz` → 암호 입력 해제).

## 7. 카메라 등록

사이트가 뜨면:

1. `/register` → ITS 탭 → 지도를 원하는 곳으로 → **현재 지도 영역 검색**
2. 카메라 선택 → 2단계에서 도로 영역을 칠하고 방향을 나눈다
3. 3단계에서 **추론 주기 10초**로 저장 (GPU 라 여유 있다) → 워커가 바로 시작
4. **5~10대** 등록

GPU 기준 여유:

| 추론 주기 | 카메라 수 |
|---|---|
| 10초 | 약 30대 |
| 5초 | 약 15대 |
| 실시간(2 FPS) | 약 3대 |

심사용으로 눈에 띄게 하려면 **잘 나오는 지점 2~3대만 실시간**, 나머지는 10초로 두는 게 좋다.

## 8. 심사 기간 동안

- **하루 한 번** 터널 주소를 직접 열어 본다. 집 인터넷이 끊겼다 붙으면 터널이 재연결되지만,
  공유기가 재부팅되면 몇 분 끊긴다.
- ITS URL 은 24시간마다 만료되는데, 서버가 켜져 있으면 워커가 알아서 다시 받아온다.
- 마스크 백업: `tar czf ~/traffic-data.tgz -C ~/traffic data`
- 로그가 쌓이면: `sudo journalctl --vacuum-time=3d`

### 이럴 때

| 증상 | 확인 |
|---|---|
| 사이트가 안 열림 | `sudo systemctl status traffic ngrok` — 둘 다 active 인가 |
| 지도에 숫자가 안 뜸 | `sudo journalctl -u traffic -n 100` — 워커가 도는가, ITS 키가 맞는가 |
| 느려짐 | `nvidia-smi` — VRAM 이 꽉 찼으면 카메라 주기를 늘린다 |
| WSL 이 죽음 | PowerShell `wsl --shutdown` 후 우분투 다시 열기 |
